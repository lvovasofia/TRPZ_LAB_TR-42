# Планувальник меню (Smart Meal Planner) — v1.0.0

Вебзастосунок для планування харчування на тиждень: користувач веде власний
довідник рецептів, складає розклад страв за днями й прийомами їжі та отримує
єдиний список покупок із підсумованими інгредієнтами.

Навчальний проєкт з дисципліни «Теорія розробки програмного забезпечення»,
КПІ ім. Ігоря Сікорського, група ТР-42.

## Можливості версії 1.0

* реєстрація та вхід (FR-01–FR-04);
* створення рецепта з перевірками та перегляд довідника (FR-05–FR-07);
* додавання рецепта в розклад і перегляд тижня 7 × 3 (FR-08–FR-10);
* генерація списку покупок із підсумовуванням однакових інгредієнтів (FR-11, FR-12).

До v1.0 **не входять**: редагування й видалення рецептів і записів розкладу,
експорт списку покупок у файл, калорійність та облік домашніх запасів.

## Технології

|Частина|Що використано|
|-|-|
|Сервер|C#, ASP.NET Core (.NET 9), мінімальний API (`MapGet` / `MapPost`)|
|Клієнт|HTML-сторінки та JavaScript (`fetch`) у папці `wwwroot`; сервер сам віддає їх у браузер|
|Дані|колекції `List<T>` / `Dictionary` у пам'яті сервера, спільний доступ захищено `lock`|
|Автентифікація|cookie-автентифікація ASP.NET Core, паролі зберігаються як хеш|
|Тести|xUnit, `Microsoft.AspNetCore.Mvc.Testing`|
|CI|GitHub Actions: складання та запуск тестів для кожного PR|

## Що потрібно встановити

* **Для запуску з вихідного коду:** [.NET 9 SDK](https://dotnet.microsoft.com/download/dotnet/9.0)
(або Visual Studio 2022 з робочим навантаженням «ASP.NET and web development»).
* **Для запуску готового пакета випуску:** .NET 9 — ASP.NET Core Runtime
(SDK теж підходить).
* Будь-який сучасний браузер (Chrome, Edge, Firefox).

Перевірити встановлення: `dotnet --list-sdks` або `dotnet --list-runtimes`.

## Запуск із вихідного коду

### Visual Studio

1. Відкрийте `EnergyAccounting.sln`.
2. Угорі виберіть проєкт запуску **EnergyAccounting.Api** і профіль **https**.
3. Натисніть **▶ https** (`F5`). Під час першого запуску погодьтеся довіряти
сертифікату ASP.NET Core для localhost.
4. Дочекайтеся в консолі рядка `Now listening on: https://localhost:7182`.
5. Відкрийте в браузері **https://localhost:7182/**.

### Командний рядок

```bash
dotnet restore
dotnet run --project src/EnergyAccounting.Api --launch-profile https
```

Потім відкрийте **https://localhost:7182/**. Адресу вводьте разом із `https://`:
порт 7182 приймає лише HTTPS. Для HTTP використовуйте порт 5208
(`http://localhost:5208/`).

### Тести

```bash
dotnet test
```

## Запуск пакета випуску v1.0.0

1. Завантажте архів `meal-planner-v1.0.0.zip` зі сторінки
[Releases](../../releases) і розпакуйте його в окремий каталог.
2. У каталозі `api` виконайте:

```bash

   ```

3. Відкрийте в браузері **http://localhost:5080/**.
4. Щоб зупинити сервер, натисніть `Ctrl+C` у вікні консолі.

## Перевірка основного сценарію

1. **Вхід / Реєстрація** — зареєструйтеся (пошта, пароль від 8 символів), потім увійдіть.
2. **Рецепти** — створіть рецепт, наприклад «Налисники»: борошно 0.5 кг, молоко 0.25 л.
3. **Розклад** — додайте рецепт на понеділок, сніданок. Повторне додавання в той
самий день і прийом їжі відхиляється з повідомленням
«Цей прийом їжі вже заплановано», розклад не змінюється.
4. **Список покупок** — натисніть «Сформувати список покупок»: однакові
інгредієнти з однаковою одиницею об'єднуються з сумою кількостей.

## Відомі обмеження v1.0

* **Дані зберігаються лише в оперативній пам'яті сервера.** Користувачі, рецепти
й розклад доступні, поки працює серверний процес. Після зупинки або
перезапуску сервера всі дані втрачаються, і потрібно знову зареєструватися.
Тому вимогу NFR-01 (збереження між перезапусками) у v1.0 не виконано;
постійне збереження в базі даних заплановано на наступну версію.
* Клієнтом є вебсторінки в `src/EnergyAccounting.Api/wwwroot`.
Консольний проєкт `src/EnergyAccounting.Client` — заготовка й у v1.0 не використовується.
* Вийти з облікового запису можна лише закриттям браузера або очищенням cookie.
