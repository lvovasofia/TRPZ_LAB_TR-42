## UC-05 Скласти розклад меню на тиждень

| Поле | Опис |
| :--- | :--- |
| **ID і назва** | UC-05 Скласти розклад меню на тиждень |
| **Мета** | Додати до тижневого розкладу запис: обраний рецепт на обраний день тижня та прийом їжі. |
| **Основний актор** | Користувач |
| **Тригер** | Користувач хоче запланувати страву на певний день і прийом їжі. |
| **Передумови** | Користувач увійшов у систему; у його довіднику є хоча б один збережений рецепт. |
| **Основний сценарій** | 1. Користувач відкриває тижневий розклад меню.<br>2. Обирає день тижня.<br>3. Обирає прийом їжі.<br>4. Обирає рецепт із довідника.<br>5. Підтверджує додавання запису.<br>6. Система перевіряє, що обраний день і прийом їжі вільні.<br>7. Система додає запис до розкладу.<br>8. Система повідомляє про успішне додавання. |
| **Альтернативний / помилковий сценарій** | **A1.** На кроці 6 обраний день і прийом їжі вже зайняті іншою стравою: система не додає запис і повідомляє, що цей прийом їжі вже заплановано. |
| **Постумови** | Успіх: запис є в тижневому розкладі Користувача. Помилка: розклад не змінено. |
| **Пов'язані вимоги** | FR-08, FR-09 |
| **Критерії приймання** | AC-08, AC-09 |

## UC-03 Створити рецепт

| Поле | Опис |
| :--- | :--- |
| **ID і назва** | UC-03 Створити рецепт |
| **Мета** | Додати новий коректний рецепт до особистого довідника користувача. |
| **Основний актор** | Користувач |
| **Тригер** | Користувач хоче зберегти новий рецепт для подальшого використання під час складання меню. |
| **Передумови** | Користувач увійшов у систему. |
| **Основний сценарій** | 1. Користувач відкриває форму створення рецепта.<br>2. Вводить назву рецепта.<br>3. Додає інгредієнти: для кожного вказує назву, кількість та одиницю вимірювання.<br>4. Підтверджує збереження рецепта.<br>5. Система перевіряє, що назва рецепта заповнена.<br>6. Система перевіряє, що рецепта з такою назвою ще немає в довіднику Користувача.<br>7. Система перевіряє, що додано хоча б один інгредієнт.<br>8. Система перевіряє, що кожен інгредієнт має назву, числову кількість більшу за нуль та одиницю вимірювання.<br>9. Система зберігає рецепт у довіднику поточного Користувача.<br>10. Система повідомляє про успішне створення рецепта. |
| **Альтернативний / помилковий сценарій** | **A1.** На кроці 5 назва рецепта порожня або містить лише пробіли: система не зберігає рецепт і просить ввести назву.<br>**A2.** На кроці 6 рецепт із такою назвою вже є в довіднику: система не зберігає рецепт і повідомляє, що назва вже використовується.<br>**A3.** На кроці 7 немає жодного інгредієнта: система не зберігає рецепт і просить додати хоча б один інгредієнт.<br>**A4.** На кроці 8 дані хоча б одного інгредієнта некоректні: система не зберігає рецепт і повідомляє, які дані потрібно виправити.<br>У кожному випадку Користувач може виправити дані та повторно підтвердити збереження. |
| **Постумови** | Успіх: новий рецепт збережено в особистому довіднику Користувача. Помилка: новий рецепт не створено, збережені дані довідника не змінено. |
| **Пов'язані вимоги** | FR-05, FR-06 |
| **Критерії приймання** | AC-05, AC-06 |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
