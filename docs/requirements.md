## 1. Межі версії v1.0

**Входить до v1.0:**
- Реєстрація нового користувача та вхід у систему.
- Створення нових рецептів із назвою та переліком інгредієнтів.
- Перегляд довідника збережених рецептів.
- Складання тижневого розкладу меню (призначення рецептів на дні тижня та прийоми їжі) і його перегляд.
- Автоматична генерація списку покупок на основі тижневого меню з підсумовуванням кількості однакових інгредієнтів.

**Не входить до v1.0:**
- Редагування та видалення існуючих рецептів.
- Редагування та видалення записів у розкладі меню.
- Експорт списку покупок у зовнішні файли (TXT, PDF тощо).
- Підрахунок калорійності страв і облік домашніх запасів продуктів.

## 2. Функціональні вимоги

| ID | Вимога | Критерій приймання |
| :--- | :--- | :--- |
| **FR-01** | Система повинна дозволяти новому Користувачу зареєструватися, вказавши електронну пошту та пароль. | **AC-01:** Після введення коректних даних обліковий запис створюється, і Користувач може увійти в систему з цими даними. |
| **FR-02** | Система повинна відхиляти реєстрацію, якщо електронна пошта вже використовується, має некоректний формат або якщо пароль коротший за 8 символів. | **AC-02:** Обліковий запис не створюється; Користувач отримує повідомлення з причиною відхилення. |
| **FR-03** | Система повинна дозволяти зареєстрованому Користувачу увійти в систему за електронною поштою та паролем. | **AC-03:** Після введення коректних даних Користувач отримує доступ до власних рецептів, розкладу меню та списку покупок і не бачить даних інших користувачів. |
| **FR-04** | Система повинна відхиляти вхід, якщо електронна пошта не зареєстрована або пароль неправильний. | **AC-04:** Доступ не надається; Користувач отримує повідомлення про неправильні дані для входу, без уточнення, що саме було невірним. |
| **FR-05** | Система повинна дозволяти Користувачу створити новий рецепт, вказавши назву та перелік інгредієнтів (назва, кількість, одиниця вимірювання). | **AC-05:** Коректний рецепт зберігається і з'являється в довіднику рецептів Користувача. |
| **FR-06** | Система повинна відхиляти збереження рецепта, якщо його назва порожня або вже є в довіднику Користувача, або якщо кількість будь-якого інгредієнта дорівнює нулю чи менша за нуль. | **AC-06:** Рецепт не зберігається; Користувач отримує повідомлення з причиною відхилення. |
| **FR-07** | Система повинна дозволяти Користувачу переглядати довідник своїх збережених рецептів із назвою та переліком інгредієнтів кожного. | **AC-07:** Усі збережені рецепти Користувача відображаються в довіднику; якщо рецептів немає, відображається повідомлення, що довідник порожній. |
| **FR-08** | Система повинна дозволяти Користувачу призначити наявний рецепт на обраний день тижня та прийом їжі. | **AC-08:** Після вибору дня, прийому їжі та існуючого рецепта запис додається до тижневого розкладу. |
| **FR-09** | Система повинна відхиляти додавання запису до розкладу, якщо обраний день тижня та прийом їжі вже зайняті іншою стравою. | **AC-09:** Запис не додається; Користувач отримує повідомлення, що цей прийом їжі вже заплановано. |
| **FR-10** | Система повинна дозволяти Користувачу переглядати тижневий розклад меню з розподілом страв за днями тижня та прийомами їжі. | **AC-10:** Усі додані записи відображаються у відповідних днях і прийомах їжі; вільні комірки відображаються як порожні. |
| **FR-11** | Система повинна формувати єдиний список покупок для тижневого розкладу, об'єднуючи інгредієнти з однаковою назвою та одиницею вимірювання в один рядок із сумарною кількістю. | **AC-11:** Якщо два або більше рецептів містять інгредієнт з однаковою назвою (без урахування регістру) та одиницею, він відображається одним рядком із сумою. Інгредієнти з різними одиницями залишаються окремими рядками. |
| **FR-12** | Система повинна повідомляти Користувача про неможливість згенерувати список покупок, якщо тижневий розклад порожній. | **AC-12:** Список не генерується; Користувач отримує повідомлення про необхідність спочатку додати страви до меню. |


## 3. Нефункціональні вимоги

| ID | Вимога | Критерій приймання |
| :--- | :--- | :--- |
| **NFR-01** | **Збереження даних:** облікові записи, рецепти, інгредієнти та записи розкладу повинні зберігатися між перезапусками системи. | **AC-NFR-01:** Після зупинки та повторного запуску системи всі раніше внесені дані доступні без втрат. |
| **NFR-02** | **Точність обчислень:** кількість інгредієнтів повинна зберігатися та підсумовуватися без втрати точності для дробових значень до 3 знаків після коми. | **AC-NFR-02:** Автоматичні тести проходять успішно, зокрема: 0.25 кг + 0.5 кг = 0.75 кг та 0.125 кг + 0.375 кг = 0.5 кг. |
| **NFR-03** | **Стійкість до помилок введення:** система повинна коректно обробляти некоректні або неповні дані у формах. | **AC-NFR-03:** Для заданого набору некоректних вводів (порожні поля, текст замість числа, від'ємні значення, дуже довгі рядки) система не завершується аварійно і показує повідомлення про помилку замість системної сторінки помилки. |
| **NFR-04** | **Захист паролів:** паролі не повинні зберігатися у відкритому вигляді. | **AC-NFR-04:** У сховищі даних для кожного облікового запису збережено хеш пароля, а не сам пароль. |
